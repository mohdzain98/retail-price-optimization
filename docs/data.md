# Data

## Getting the dataset

The project uses dunnhumby's **Breakfast at the Frat** dataset. It is free but licensed, so it is not included in
this repository.

1. Open [dunnhumby source files](https://www.dunnhumby.com/source-files/) and choose *Breakfast at the Frat*. A short
   form is required.
2. Put `dunnhumby - Breakfast at the Frat.xlsx` in `data/raw/`.
3. Run `make data-check` to confirm the file and its sheets match `config/config.yaml`.

`data/raw/` and `data/processed/` are git-ignored, so the data cannot be committed by accident.

## Raw workbook

Each sheet has a title row above the header; the loader detects the header automatically. Raw columns are renamed
to canonical names through `data.columns` in the config.

| Sheet | Grain | Columns used |
|---|---|---|
| `dh Transaction Data` | store × UPC × week (524,950 rows) | `WEEK_END_DATE`, `STORE_NUM`, `UPC`, `UNITS`, `VISITS`, `HHS`, `SPEND`, `PRICE`, `BASE_PRICE`, `FEATURE`, `DISPLAY`, `TPR_ONLY` |
| `dh Products Lookup` | UPC | `UPC`, `DESCRIPTION`, `MANUFACTURER`, `CATEGORY`, `SUB_CATEGORY`, `PRODUCT_SIZE` |
| `dh Store Lookup` | store | `STORE_ID`, `STORE_NAME`, `ADDRESS_STATE_PROV_CODE`, `SEG_VALUE_NAME` |

`FEATURE` means the product was in the in-store circular, `DISPLAY` means it was on in-store display, and `TPR_ONLY`
means a temporary price reduction with neither feature nor display.

## Processed outputs

All files are in `data/processed/`. Column names are defined once, in `src/schema.py` (`Col`).

### `panel.parquet`: one row per product × week (8,304 rows, 55 products, 156 weeks)

| Group | Columns |
|---|---|
| Keys | `upc`, `week` |
| Sales | `units`, `spend`, `visits`, `hhs`, `n_stores` |
| Price | `price` (spend ÷ units), `base_price` |
| Promotion | `feature`, `display`, `feature_display`, `tpr`: share of selling stores, 0–1; `promo_flag` (0/1); `pl1..pl3`: promo flag lagged 1–3 weeks |
| Product | `description`, `manufacturer`, `category`, `sub_category`, `product_size` |
| Eligibility | `eligible`, `filter_reason` |
| Model features | `ln_units`, `ln_price` = `ln_base_price` + `ln_promo_price`, `discount_depth`, `ln_n_stores`, `sin_1..3`, `cos_1..3`, `holiday_week`, `thanksgiving`, `christmas`, `super_bowl`, `ln_trend` (residual LOESS trend) |
| Time | `t` (week index), `split` (`train` / `test`) |

### Elasticity outputs

| File | Content |
|---|---|
| `elasticities.parquet` | Final table, one row per product. Regular: `elasticity`, `elasticity_low`, `elasticity_high` (94% interval), `elasticity_source`, `impute_reason`. Promo: `promo_elasticity`, `promo_elasticity_low`, `promo_elasticity_high`, `promo_source`, `promo_impute_reason`. Also `model` (the selected model, empty if imputed), `train_mape`, `train_r2`, and product attributes |
| `elasticities_all_models.parquet` | Every model's estimates, intervals, `train_mape`, `train_r2` and `passes_gates` per product (long format) |
| `model_comparison.parquet` | Per model: holdout WAPE, median regular elasticity, share within bounds, share passing gates, fit time |
| `elasticity_draws.parquet` | Bayesian posterior draws per product (`draw`, `upc`, `elasticity`, `promo_elasticity`) |
| `elasticity_models.pkl` | Fitted models (pickle) used by the baseline stage; regenerated by `make elasticity` |
| `raw_*.parquet` | Cache of the three raw sheets |

### Baseline outputs

| File | Content |
|---|---|
| `baseline.parquet` | Panel columns plus, per product-week: `ln_pred`, `baseline_model`, effect terms (`price_effect`, `promo_effect`, `pantry_effect`, `error_effect`), `base_raw`, one `rule_*` flag per bad-baseline rule, `baseline_units`, `baseline_fix` (`raw` / `rolling_mean` / `actual_volume`), `incremental_units`, and lifts (`price_lift`, `promo_lift`, `pantry_lift`, `error_lift`) that sum to the incremental units |
| `baseline_summary.parquet` | Per product: units, baseline units, summed lifts, `baseline_share`, `promo_week_lift` (mean units ÷ baseline − 1 in promo weeks), weeks per fix type |

### Optimization outputs

| File | Content |
|---|---|
| `price_recommendations.parquet` | One row per product **and objective** (`objective` = `profit` / `revenue`). Contains: inputs (`current_price`, `base_volume_weekly`, `elasticity` + interval, `unit_cost`, pack size); weekly KPIs per scenario (`{current,optimal,recommended,linear_formula}_{price,volume,revenue,profit}`, always at real unit cost); `price_ratio` (recommended change); `linear_formula_price`; `safeguard_applied`; the rule check (`effective_cost`, `own_optimal_price`, `expected_direction`, `actual_direction`, `rule_status`); and robustness percentiles `optimal_price_p05/p50/p95` |
| `optimization_summary.parquet` | Per objective, one row per solver (`LD_SLSQP`, `LN_COBYLA`, `GN_ISRES`) and per scenario (`recommended`, `linear_formula`). Contains weekly totals, % change vs current, `annual_profit_delta`, evaluations, time, status and `max_constraint_violation` |

### Forecast and promo outputs

Every table except the backtest has an `objective` column (`profit` / `revenue`); each goal uses its own Phase 4
prices.

| File | Content |
|---|---|
| `forecast.parquet` | One row per product × horizon week: `forecast_method`, `seasonal_index` (forecast ÷ base volume), `forecast_baseline_current_prices`, `forecast_baseline_units` (at recommended prices), product attributes, `current_price`, `regular_price`, the MILP plan for that week (`tactic`, `discount_depth`, `promo_price`, `promo_units`, `trade_spend`, incremental units, revenue and profit; empty when no promo) and `plan_units` (units with promo lifts and pantry dips) |
| `forecast_backtest.parquet` | One row per forecast method (`naive_flat`, `seasonal_index`, `sarimax`, `xgboost`): `holdout_wape`, `holdout_bias`, scored rows, fit seconds and `selected` (the method used for the horizon) |
| `promo_candidates.parquet` | Every product × week × tactic × depth option: `lift`, `promo_units`, `pantry_dip_units`, `incremental_units`, `incremental_revenue`, `incremental_profit`, `fixed_cost`, `trade_spend`, `gain` (the goal's incremental value) and `roi` (gain ÷ spend). The simulator can re-plan from this table |
| `promo_plan.parquet` | Chosen options per `scenario` (`last_year_calendar`, `milp_at_last_year_spend`, `greedy_plan`, `milp_plan`) with the `budget` each was solved for |
| `budget_frontier.parquet` | One row per budget: `trade_spend`, `gain`, `n_promos`, `marginal_return` and the `recommended_budget` flag |
| `promo_summary.parquet` | Horizon totals per scenario (also current and recommended prices with no promo): volume, revenue, profit (net of fees), trade spend, promos, and % change vs current prices with no promo |
